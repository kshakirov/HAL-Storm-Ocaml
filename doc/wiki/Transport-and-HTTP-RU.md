# Транспорт и HTTP

[English](Transport-and-HTTP) · [Home](Home) · [Русская главная](Home-RU)

Текущий путь: Eio accept → обработчик клиента → `single_read` → `Cstruct.sub buffer 0 read_bytes` → `httpRequestParse` → `wirth_parser`.

У соединения свой переиспользуемый буфер на 1028 байт. Обновлённое состояние HTTP передаётся следующему чтению. Смещения абсолютные; фрагменты запроса распознаватель не накапливает. JSON Tape к транспорту ещё не подключена.

Это прототип: синтаксис HTTP, framing, тела, EOF и pipelining не завершены. И успех, и ошибка сейчас получают одинаковый минимальный ответ 200. Это не готовое поведение HTTP-сервера.

Есть модель `doc/automaton_1.smv`. Она не доказывает корректность всей реализации: соответствие коду и усиление свойств остаются открытыми. См. [Research](Research-RU).

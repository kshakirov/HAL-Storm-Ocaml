# Структурная Tape JSON

[English](JSON-Structural-Tape) · [Home](Home) · [Русская главная](Home-RU)

Tape — `Dynarray` записей: тег, абсолютный `source_offset`, длина исходного диапазона `length`, необязательный `link`. Роли атомов — Key и Value. Объектное дерево JSON не строим, байты в записи не копируем. Источник должен оставаться доступным, если потребителю позже нужны сами байты диапазона.

Стек хранит frame контейнера: индекс открытия в Tape и фазу разбора. Это не дерево результата. На одном уровне меняется состояние верхнего frame; вложенность добавляет frame, закрытие снимает его.

На открытии добавляем запись и запоминаем индекс. На закрытии по нему напрямую обновляем открытие, добавляем закрытие и связываем записи. Поиск по Tape при построении не нужен. У атома одна запись и `link=None`.

Текущая семантика диапазонов: открывающая запись охватывает весь контейнер со скобками; закрывающая — один байт. Ключ включает обе кавычки. Это отличается от раннего импортированного плана, где у открытия длина один байт; снимок оставляем как историю.

Главный парсер открывает вложенные контейнеры и возвращает управление родителям на закрывающих скобках или запятой. Контейнер сам съедает свою закрывающую скобку. Открывающую скобку при передаче главному оставляем непрочитанной.

Тесты покрывают пустые контейнеры, простые атомы, несколько полей/элементов, вложенность и отдельные случаи продолжения после дочернего контейнера. Пробелы: space, tab, LF и CR. Общий тест проверяет все 11 записей, смещения и ссылки; пробел внутри ключа сохраняется. После запятой массива `ExpectingArrayValue` откладывает создание атома до первого непробельного байта.

Ограничения: строки-значения и экранирование ещё не реализованы; хвостовые пробелы простого атома пока попадают в его длину. Продолжение между окнами и ошибки не завершены. Проверяемый успешный проход пока возвращает `Wip`, публичная семантика завершения не утверждена. Срезы Cstruct, записи контекста и элементы стека требуют отдельной оценки аллокаций.

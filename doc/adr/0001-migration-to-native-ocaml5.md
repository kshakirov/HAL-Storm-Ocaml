# ADR-0001: Миграция ядра сервера HAL-Storm на нативную платформу OCaml 5

## Статус
Принято (Approved) — Июль 2026

## Контекст
В ходе разработки первой аппроксимации высокопроизводительного парсера HAL-Storm на языке F# (.NET 9) мы столкнулись с жестким ограничением рантайма Common IL. Попытка построить комбинаторы парсеров без аллокаций над стековыми структурами памяти `ReadOnlySpan<byte>` привела к постоянной войне с компилятором (ошибки `FS0412`, `FS1198`, `FS0670`). Платформа .NET запрещает передавать `byref`-структуры внутрь generic-вызовов и кучевых замыканий.

Для достижения максимальной производительности на уровне физики железа без искусственных ограничений виртуальной машины принято решение перенести чертежи движка на нативный **OCaml 5**.

## Решение
1. **Смена платформы**: Полный отказ от экосистемы .NET/F# в пользу нативного компилятора `ocamlopt`, собирающего чистые бинарники (x86_64 / ARM64).
2. **Асинхронность нового поколения**: Использование библиотеки **Eio** (стандарт OCaml 5), работающей на встроенных в рантайм обработчиках эффектов (Effect Handlers). Это дает прямой доступ к `io_uring` (Linux) и оптимизациям Apple Silicon (macOS) без аллокаций в куче.
3. **Мономорфизация типов**: В OCaml дженерики и структуры не имеют ограничений CLR. Локальные типы данных эффективно стираются и раскладываются компилятором по регистрам процессора.

## Последствия
* **Плюсы**: Чистый математический синтаксис, микроскопический рантайм, отсутствие костылей `IsByRefLike` и сверхбыстрое выделение памяти (bump allocation) на уровне сдвига указателя.
* **Минусы**: Утеряна совместимость с библиотеками .NET (не критично для проекта, создаваемого с нуля).


# 🗺️ Отчет об Архитектурном Шаге: Миграция на Кремний OCaml 5

## 1. Зачистка и развертывание плацдарма
* **Переход на Натив**: Мы полностью ликвидировали проект на F#/.NET из-за неустранимого конфликта тяжелого объектного рантайма CLR с нашими стековыми комбинаторами.
* **Новая Гавань**: Создан и настроен чистый нативный репозиторий `kshakirov/HAL-Storm-Ocaml` под управлением сборщика Dune. Тулчейн OCaml 5.1.0 успешно развернут на macOS (Apple Silicon) без единой осечки.
* **Штабная документация**: В корень зашит манифест `README.md`, а в журнал `doc/adr/` официально добавлен документ `0001-migration-to-native-ocaml5.md`, фиксирующий физику нашего перехода.

## 2. Интеграция Асинхронного Реактора (`bin/main.ml`)
* В точку входа интегрирован современный сетевой движок **Eio**. 
* Мы получили честный нативный Event Loop, который на Mac асинхронно управляет потоками на уровне ядер процессора (через GCD/kqueue), обеспечивая вывод логов (`traceln`) и обработку событий без аллокаций промисов в куче.

## 3. Фиксация Логики Автомата (`lib/parser.ml`)
* **Разделение Вирт/Марков**: Четко разграничили зоны влияния. На этапе разметки сырого буфера байт правит детерминированный автомат Вирта. Алгоритмы Маркова (НАМ) включатся позже для трансформации токенов.
* **База ДКА**: Заложен перечисляемый тип состояний первой строки HTTP (`ParseMethod`, `ParseUri`, `ParseVersion`). 
* **Физика переходов**: Утвердили использование хвостовой рекурсии. Компилятор `ocamlopt` сотрет вызовы функций и превратит ветвление состояний в плоскую ассемблерную таблицу переходов с инструкциями `jmp`, гарантируя бесконечный бег автомата с нулевым размером стека.

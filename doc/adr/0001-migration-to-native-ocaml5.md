# ADR-0001: Миграция ядра сервера HAL-Storm на нативную платформу OCaml 5

## Статус
Принято (Approved) — Июль 2026

## Контекст
В ходе разработки первой аппроксимации высокопроизводительного парсера HAL-Storm на языке F# (.NET 9) мы столкнулись с жестким ограничением рантайма Common IL. Попытка построить комбинаторы парсеров без аллокаций над стековыми структурами памяти `ReadOnlySpan<byte>` привела к постоянной войне с компилятором (ошибки `FS0412`, `FS1198`, `FS0670`). Платформа .NET запрещает передавать `byref`-структуры внутрь generic-вызовов и кучевых замыканий.

Для достижения максимальной производительности на уровне физики железа без искусственных ограничений виртуальной машины принято решение перенести чертежи движка на нативный **OCaml 5**.

## Решение
1. **Смена платформы**: Полный отказ от экосистемы .NET/F# в пользу нативного компилятора `ocamlopt`, собирающего чистые бинарники (x86_64 / ARM64).
2. **Асинхронность нового поколения**: Использование библиотеки **Eio** (стандарт OCaml 5), работающей на встроенных в рантайм обработчиках эффектов (Effect Handlers). Это дает прямой доступ к `io_uring` (Linux) и оптимизациям Apple Silicon (macOS) без аллокаций в куче.
3. **Мономорфизация типов**: В OCaml дженерики и структуры не имеют ограничений CLR. Локальные типы данных эффективно стираются и раскладываются компилятором по регистрам процессора.

## Последствия
* **Плюсы**: Чистый математический синтаксис, микроскопический рантайм, отсутствие костылей `IsByRefLike` и сверхбыстрое выделение памяти (bump allocation) на уровне сдвига указателя.
* **Минусы**: Утеряна совместимость с библиотеками .NET (не критично для проекта, создаваемого с нуля).

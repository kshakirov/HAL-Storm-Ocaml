## Контекст

В `lib/markov_parser.ml` начат минимальный эксперимент над упорядоченными правилами `(левая часть, правая часть)`. Текущий прототип сканирует вход слева направо, проверяет правила в текущей позиции и возвращает первое найденное правило вместе с оставшимся `Eio.Buf_read`.

Это пока поиск применимого правила, а не законченный нормальный алгоритм Маркова: подстановка и повторное применение правил ещё не реализованы.

## Перспективная цель

Проверить, может ли марковское переписывание стать отдельным слоем HAL-Storm после потоковой разметки Вирта:

```text
bytes -> slices/tokens -> ordered rewrite rules -> application state
```

## Вопросы исследования

- Точно определить семантику выбора: приоритет правила или приоритет самой левой позиции.
- Сверить определение с первоисточником А. А. Маркова «Теория алгорифмов» (1954), глава II, §3.
- Определить результат поиска без фиктивного правила-сентинела.
- Проверить совпадение правила на границе входных окон.
- Отделить поиск от подстановки и условие обычной остановки от заключительного правила.
- Сохранить потоковый принцип: состояние переносится между окнами, уже прочитанные байты не просматриваются без необходимости.

## Текущий проверяемый шаг

Добавлен отдельный тест `test/test_markov.ml`: для строки `Tell me why` правило `Te -> AA` находится в начале входа и возвращается как найденное.

## Критерий ближайшего этапа

Минимальный тест должен утверждением проверять найденное правило и отдельно проверять отсутствие совпадения. Реализацию подстановок добавлять только после фиксации семантики выбора.
